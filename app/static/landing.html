The problem

The request sounds safe.
The graph knows it isn't.

Agents act on one line of text. The damage is usually two or three hops away, in who owns what and what depends on it. A model can't reliably see that. A graph query can.

What the agent is asked

"Contractor 17 is leaving today. Disable their account and revoke their deploy credential."

id-contractor-17 -[OWNS]-> svc-billing -[DEPENDS_ON]-> db-billing-primary
What ActionGraph answers

BLOCK. Billing is critical and would be left with no eligible owner. The other name on it is a former employee who no longer counts. Nothing ran. Suggested repair: engineer-9 already runs payments on the same database.

How it works

Prove before act. Verify after act.

Every verdict is computed in code from the graph, not by a model. The model only proposes.

Propose

An agent, the web app or the CLI submits a plan: ordered actions such as assign owner, disable identity, revoke credential.

POST /v1/plans

Preflight on the graph

Bounded Cypher reads the live FalkorDB state. The plan is projected in memory and checked against named invariants, with the multi-hop path as evidence.

BLOCK NEEDS_REVIEW PASS

A person approves

Even a passing plan waits. The agent has no approve tool, so it can't approve its own plan. The graph is checked again right before the first write.

APPROVED

Execute and read back

Each step is read back from the graph. VERIFIED only if the read-back matches. A timeout is UNKNOWN; half done is PARTIAL_FAILURE.

VERIFIED

Why a graph

Delete one edge. The verdict flips.

Same plan, same code. With engineer-9 -[OWNS]-> svc-billing in the graph, disabling the contractor passes. Delete only that edge and it's blocked. The graph is doing the work, not a prompt. It's a test in CI and step 5 of the demo.

Built for Track 01

Agents that act on connected data.

What a judge can check in five minutes.

The graph is load-bearing

FalkorDB holds identities, services, resources, credentials and invariants. Verdicts, evidence paths and the suggested repair all come from Cypher.

Honest about failure

Fail closed when the graph is down. Timeouts are UNKNOWN. Reconcile reads the live graph and reports PARTIAL_FAILURE instead of a fake rollback.

Shipped like a product

Live on AWS Lightsail with HTTPS. GitHub Actions runs every test against real FalkorDB, then deploys with OIDC and rolls back on failure.
